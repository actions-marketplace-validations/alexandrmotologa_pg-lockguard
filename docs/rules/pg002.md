# PG002: DROP INDEX without CONCURRENTLY

## Lock Level Acquired
`ACCESS EXCLUSIVE`

## Problem
Dropping an index without CONCURRENTLY takes an ACCESS EXCLUSIVE lock on the indexed table until any pending transactions referencing that table finish, blocking all concurrent queries.

## Dangerous Pattern
```sql
DROP INDEX idx_users_email;
```

## Safe Zero-Downtime Recipe
```sql
-- Step 1: Drop index concurrently outside a transaction block
DROP INDEX CONCURRENTLY IF EXISTS idx_users_email;
```
