# PG004: ADD FOREIGN KEY without NOT VALID

## Lock Level Acquired
`SHARE ROW EXCLUSIVE`

## Problem
Adding a foreign key constraint without NOT VALID forces PostgreSQL to sequentially scan the target table to verify all existing rows, blocking concurrent updates and deletes.

## Dangerous Pattern
```sql
ALTER TABLE orders ADD CONSTRAINT fk_orders_user_id FOREIGN KEY (user_id) REFERENCES users(id);
```

## Safe Zero-Downtime Recipe
```sql
-- Step 1: Add foreign key with NOT VALID (instant metadata lock, no table scan)
ALTER TABLE orders ADD CONSTRAINT fk_orders_user_id FOREIGN KEY (user_id) REFERENCES users(id) NOT VALID;

-- Step 2: Validate constraint in a separate transaction (reads and writes remain active)
ALTER TABLE orders VALIDATE CONSTRAINT fk_orders_user_id;
```
