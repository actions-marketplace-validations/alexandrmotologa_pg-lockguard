# PG005: Incompatible Column Type Alteration

## Lock Level Acquired
`ACCESS EXCLUSIVE`

## Problem
Changing a column type to a non-binary-compatible type (such as integer to bigint or numeric precision changes) requires PostgreSQL to rewrite every row on disk under an ACCESS EXCLUSIVE lock.

## Dangerous Pattern
```sql
ALTER TABLE users ALTER COLUMN id TYPE bigint;
```

## Safe Zero-Downtime Recipe
```sql
-- Step 1: Add new column
ALTER TABLE users ADD COLUMN id_new bigint;

-- Step 2: Dual-write trigger for new rows
CREATE OR REPLACE FUNCTION tf_sync_id() RETURNS trigger AS $$
BEGIN
  NEW.id_new := NEW.id::bigint;
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- Step 3: Backfill historical data in batches
UPDATE users SET id_new = id::bigint WHERE id_new IS NULL;

-- Step 4: Swap columns
```
