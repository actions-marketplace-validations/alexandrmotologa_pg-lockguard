# PG003: ADD COLUMN NOT NULL without Constant Default

## Lock Level Acquired
`ACCESS EXCLUSIVE`

## Problem
Adding a NOT NULL column without a constant default on existing tables forces PostgreSQL to rewrite every row on disk while holding an ACCESS EXCLUSIVE lock.

## Dangerous Pattern
```sql
ALTER TABLE users ADD COLUMN score INT NOT NULL;
```

## Safe Zero-Downtime Recipe
```sql
-- Step 1: Add column as nullable
ALTER TABLE users ADD COLUMN score INT;

-- Step 2: Backfill historical rows in small batches
UPDATE users SET score = 0 WHERE score IS NULL;

-- Step 3: Add NOT VALID check constraint (instant metadata update)
ALTER TABLE users ADD CONSTRAINT chk_users_score_not_null CHECK (score IS NOT NULL) NOT VALID;

-- Step 4: Validate constraint in a separate transaction
ALTER TABLE users VALIDATE CONSTRAINT chk_users_score_not_null;
```
